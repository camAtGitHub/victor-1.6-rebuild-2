# Host VizManager — implementation plan

**Path:** `docs/mapping/VIZMANAGER-HOST-PLAN.md`  
**Status:** plan only · **UI/UX locked 2026-08-19**  
**Mapped:** 2026-08-19  
**For agentic workers:** execute via worktree-isolated implementers + an orchestrator reviewer. The `## PR Plan` section is a DAG for `/execute-plan`. **Before any UI code:** read `docs/mapping/vizmanager-design/MASTER.md` (this plan’s Design Spec is the short form).

**Goal:** A mature Windows + Linux host Viz client that speaks the engine’s existing UDP Viz protocol (not WebViz), unpacks CLAD `MessageViz`, and renders at least: BehaviorStackDebug, RobotStateMessage, JPEG image reassembly + camera overlays, 2D paths/cubes, and a 3D clone of `webotsCtrlViz`.

**Architecture:** Host is the UDP **server** on port 5252. Engine is the UDP **client**. Copy consumer logic from `simulator/controllers/webotsCtrlViz/vizControllerImpl.cpp` and the image assembler from `engine/encodedImage.cpp`. Aim the robot with the stock G2E `RedirectViz` path already proven in `docs/mapping/viz-udp-poc/redirect.py`. Do **not** rewrite `engine/viz/vizManager.cpp` except optional later niceties (`RedirectVizTo` is already there for rebuilt firmware).

**Tech stack (locked):** Python 3.10+ (stdlib `socket` is the only portable UDP we have; C++ `UdpClient`/`UdpServer` are POSIX-only). Generated CLAD Python (`clad/Makefile` `python` / `vizPython`). OpenCV for JPEG (`cv2.imdecode`, same as `EncodedImage`). pygame for chrome + 2D + camera. vispy for 3D. Colors/type only from `vizmanager/theme.py`. pytest. Package as `tools/vizmanager/` so Win/Linux share one tree.

## Phase 0 — Allowed APIs (copy these; do not invent)

### Transport (must implement exactly)

| Fact | Source |
|---|---|
| Engine = `UdpClient`; host = `UdpServer` on **5252** | `clad/vizSrc/clad/types/vizTypes.clad:11`; `webotsCtrlViz.cpp:52–53` |
| Max datagram **2848** | `vizTypes.clad:19`; `vizManager.cpp` pack buffer |
| Handshake 8 bytes `ANKICONN` (`{'A','N','K','I','C','O','N','N'}`) | `UdpServer.h:13`; `UdpClient.cpp:114–116`; `UdpServer.cpp:176–181` |
| Packet = `MessageViz.Pack` (uint8 tag + payload, little-endian) | `vizManager.cpp:128–131`; CLAD `CPP_emitter` |
| Engine never Recv on viz socket | `vizManager` send-only after Connect |
| Send is silent unless `ANKI_DEV_CHEATS && _isConnected && kSendAnythingToViz` | `vizManager.cpp:117–122` |
| Images extra-gated by `_sendImages` | `vizManager.cpp:786–790` |
| Default `_isConnected=false`, `_sendImages=false` until RedirectViz | ctor `vizManager.cpp:103–106` |

**Copy:** handshake + bind from `docs/mapping/viz-udp-poc/listen.py`.  
**Copy:** stock aim-the-robot from `docs/mapping/viz-udp-poc/redirect.py` (UI :5200, register :5103, G2E `RedirectViz` tag **0x6F**, ping keep-alive).  
**Do not** implement a second protocol. **Do not** use WebViz `:8888` as the Viz stream.

### Connect (stock firmware)

| Step | Source |
|---|---|
| G2E `RedirectViz { uint32 ipAddr }` | `messageGameToEngine.clad:194–196` |
| Handler decodes four host-endian octets, `Connect(ip, 5252)`, `EnableImageSend(true)`, `EraseAllVizObjects` | `cozmoEngine.cpp:645–666` |
| Fake UI device **id 1** auto-connects (`UiMessageHandler(1)`) | `cozmoEngine.cpp:191`; `uiMessageHandler.cpp:597–604` |
| UI ping timeout **5000 ms** calls `VizManager::Disconnect()` | `uiMessageHandler.cpp:50–52, 157–161` |
| Registration one-shot ads expire **0.25 s** | `ROBOT_ADVERTISING_TIMEOUT_S` |

G2E tags (dumped from this tree, claimed match stock 1.6): `AdvertisementRegistrationMsg=0x4C`, `Ping=0x4E`, `RedirectViz=0x6F`. E2G `Ping=0x1F`.

### Image reassembly (copy `EncodedImage::AddChunk`)

- Schema: `clad/src/clad/types/imageTypes.clad:22–32`. Chunk payload max **1200**.
- Key frame by **`imageId`**, not timestamp. New id must start at `chunkId==0`. In-order `chunkId`. Complete when `chunkId == imageChunkCount-1` and received count matches.
- Viz camera path emits **standard JPEG** (`ImageEncoding::JPEGColor`), OpenCV `imencode(".jpg")`. **Do not** invent MiniGray headers for this feed.
- `displayIndex==0` is camera. ≥1 are debug images.
- Overlays are **not** queued: JPEG chunks first, then `Camera*` packets paint until the next complete camera frame pastes and wipes. Copy `vizControllerImpl.cpp:567–717`.
- Images require `VisionMode::Viz` **and** `_sendImages`. RedirectViz sets the latter; user/console must enable Viz mode (or `ImageRequest` Stream).

### HUD / stack / robot state

- `BehaviorStackDebug { string debugStrings[uint_8] }` — one `GetDebugLabel()` per stack entry, bottom-to-top. Sender: `stackVizMonitor.cpp:64–81`. Draw: `vizControllerImpl.cpp:918–933` (white lines, clear each message).
- `RobotStateMessage` wraps **structure** `RobotState` (`robotStatusAndActions.clad:111–135`) plus engine extras (IMU temp, cliff thresholds, video/image periods, locked tracks, battery, off-treads). Sender: `robot.cpp:1187–1206`. Draw: `vizControllerImpl.cpp:756–788`.
- `SetRobot` is the 3D/2D pose ghost (metres + head/lift). Distinct from `Object` robot marker. Sender: `DrawRobot(pose,head,lift)` ← `robot.cpp:1345` if physical + `ANKI_DEV_CHEATS`.

### 3D / 2D world maps (copy storage, replace Webots draw)

Copy maps and erase rules from `vizControllerImpl.cpp:1185–1362` and PhysViz `ALL_*` erase (`physVizController.cpp` — **better** than VizControllerImpl for `EraseAllPaths` / `EraseAllQuads`).

| Store | Key | Draw |
|---|---|---|
| objects | `objectID` | cuboid / charger / predock / head / pose marker |
| segments | string identifier | GL lines |
| quads | `(quadType, quadID)` | wire quads |
| paths | `pathID` | line strips + arcs (tessellate 0.2 rad like PhysViz) |

Object types: `vizTypes.clad` `VizObjectType`. Pose: metres, deg axis-angle, `PreComposeWith` origin from `SetVizOrigin` (mm→m). Color: Anki `0xRRGGBBAA`.

**Webots-only — do not copy:** `Supervisor`, `Display`, `importMFNodeFromString`, proto `WireframeCuboid` etc. Replace with vispy/OpenGL.

### Anti-patterns

- Do not use C++ `UdpClient.cpp` on Windows (POSIX `sys/socket.h`).
- Do not treat WebViz `:8888` as Viz.
- Do not wait for a `DisplayImage` message (does not exist).
- Do not require `RedirectVizTo` (absent on unrebuilt robots).
- Do not unpack MiniJPEG for the camera path.
- Do not implement `FaceDetection` / `TrackerQuad` / `VisionMarker` senders.
- Do not open UDP 5252 on the robot.
- Do not flatten `RobotStateMessage` with E2G `RobotState` (different CLAD).
- Do not edit `docs/architecture/` or robot firmware for v1 except existing `RedirectVizTo`.
